- 이력서: `안순용_이력서(5).pdf` 원본을 `assets/안순용_이력서.pdf`로 적용
- 수정한 HTML 부분: 상단 및 CONTACT의 이력서 링크 캐시 버전 2곳
- 나머지 CSS, JavaScript, 이미지는 기존 포트폴리오 리소스를 유지

## GitHub Pages

ZIP 압축을 해제하고 `index.html`, `style.css`, `script.js`, `projects-data.js`, `project-visuals.js`, `assets/`를 저장소 루트에 업로드하면 됩니다.
기존 GitHub 저장소에서 PDF 교체만 필요하다면 `index.html`과 `assets/안순용_이력서.pdf` 두 파일을 업데이트하세요.


## V6.3 — 시설·구축 운영 기준 3건으로 재구성
- CASE 01의 운영체계 사례를 시설 유지보수 기준, 사업장 구축 절차, 현장 부담당자·본사 담당자 공종별 점검 체크리스트의 3건으로 통일했습니다.
- 대표 성과, 첫 번째 주요 성과 카드, 상세 사례 팝업(문제·실행·성과·시각화), 상단 업무 키워드, 주요 업무, 경력 태그의 관련 설명을 변경했습니다.
- 주요 성과 카드 내부에 01·02·03 번호, 처리 흐름, 담당자별 역할 카드와 반응형 레이아웃을 추가했습니다.


## V6.4 — 실제 규정/조직도/구축 플로우 반영 (공개 안전성 고려)
- 시설유지보수관리 기준(2026.01.01 제정)을 근거로 접수→검토→협력사 조치→완료 확인의 책임·절차를 상세화했습니다. 긴급 선조치·즉시 보고, 분기 점검, 계절별 예방점검, 업체평가 등 범주를 요약했습니다.
- 시설구축 플로우 차트의 사전기획, 법규·입지 적합성 판단, 설계·시공, 검사/사용승인, 운영 전환 구조를 재구성하고 보완·재검토 분기를 시각화했습니다.
- 유지보수 기준의 별표인 '시설관리자용'과 '시설담당자용' 점검표를 구별하고 시설관리조직도에 근거해 사업장 담당과 본사의 역할을 재정의했습니다.
- 정확성을 위해 '규정 3건 제정'으로 표시하지 않고 '운영문서 3종 정립'으로 표기합니다. 공종별 체크리스트는 독립 규정이 아닌 규정의 별표입니다.
- **공개용 비식별 처리:** 조직도 내 직원 이름, 동탄 순환 담당 인원, 내부 승인·계약 금액, 보안·시설의 상세 기술적 취약 정보, 규정 PDF 원본을 포트폴리오에 포함하지 않았습니다. 새 이미지는 회사 기밀 문서 스캔이 아닌 HTML/CSS로 재구성한 설명 그림입니다.
- 업무체계 문서화와 실제 정량 개선 성과는 구분합니다. 새 개선 효과 수치를 만들거나 암시하지 않았습니다.


## V6.7 — 채용담당자용 시각화 확대 · 모바일 재배치
- 주요 성과 CASE 01을 PC에서 전체 폭으로 확장하고, 3종 운영문서를 요약 카드·박스형 흐름도·현장/본사 비교 카드로 구성했습니다.
- CASE 02는 PC에서 사진과 텍스트를 나란히, 모바일에서는 사진을 먼저 보여주는 레이아웃으로 변경했습니다.
- 모바일 360~600px에서 각 프로세스를 세로 방향으로 재배치했으며, 작은 원형 업무 키워드를 터치 가능한 3열 버튼으로 바꿨습니다.
- 상세 모달의 공종별 점검 차이와 시즌별 관리 내용을 구체화했습니다.
- 공개용 문서이므로 내부 인명·승인 금액 등 민감한 상세 정보를 포함하지 않았습니다. 사이트 전반의 업체 호칭은 ‘협력사’로 통일했습니다.
